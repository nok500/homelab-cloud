## Rootless BuildKit on Talos

Talos ships **`user.max_user_namespaces = 0`**, which blocks user namespaces for everyone (found 2026-11-24). Options
were: turn them on and run BuildKit rootless, the same with seccomp `Unconfined`, or a **privileged** BuildKit in an
isolated namespace. Chosen (2026-11-24): **rootless, with user namespaces on and a custom seccomp profile**, so
namespace `ci` stays at Pod Security **`baseline`** and no pod in the lab needs `privileged`.

- **Workers** (Talos patch in `terraform/talos/main.tf`): `user.max_user_namespaces = 11255`, and the profile
  `buildkit-rootless.json`, written by Talos to `/var/lib/kubelet/seccomp/profiles/`. Applied live without a reboot.
- **The profile** (`terraform/talos/seccomp/buildkit-rootless.json`, generated by `scripts/seccomp-buildkit.py`) is
  Docker's default (moby/profiles `seccomp/v0.3.0`, pinned by sha256) plus two rules:
  - allow `clone`/`unshare`/`setns`/`mount`/`umount2`/`pivot_root` and the new mount API. Docker allows these only
    with CAP_SYS_ADMIN, and containerd resolves that condition from the container's own capabilities when it loads
    the profile, so a rootless pod never gets them, even inside its own user namespace.
  - `keyctl`/`add_key`/`request_key` return **ENOSYS** instead of Docker's EPERM. They stay blocked, but runc
    skips its session keyring only on ENOSYS. With EPERM, every `RUN` step failed: "unable to join session
    keyring: operation not permitted".
- **The build pod**: uid 1000, `privileged: false`, `seccompProfile: Localhost`; privilege escalation allowed,
  because rootlesskit maps uids through the setuid `newuidmap`/`newgidmap` helpers. BuildKit runs with
  `--oci-worker-no-process-sandbox`. With it, build steps share BuildKit's PID namespace. Without it they would need
  an unmasked `/proc`, which Pod Security only allows at `privileged`. A build step can therefore see and signal
  buildkitd, which runs in the same pod: acceptable for the lab's own repo.
- **Everyone else is unaffected**: user namespaces are on, but `RuntimeDefault` seccomp, which every other pod
  uses, still refuses `unshare(CLONE_NEWUSER)` without CAP_SYS_ADMIN. Only a pod that names the Localhost profile
  can create one, and Pod Security keeps that to namespaces at `baseline` or looser.

Tested live before deploying (2026-11-24, throwaway namespace): the rootless build pulled busybox and ran a `RUN`
step (root inside the user namespace, uid 1000 outside); a `RuntimeDefault` pod got `unshare: Operation not permitted`.

## First deploy (2026-11-24): three fixes

- **Argo server exited at start**: the chart lets it read only the Secrets named in `server.sso.rbac.secretWhitelist`
  (plus its own `sso`), so `argo-server-sso` is listed there with `argo-admin.service-account-token`.
- **`ci-poll`'s submit step failed**: Argo's `init` container writes the manifest to `/tmp`, which the read-only
  executor root doesn't allow; a `podSpecPatch` gives it `main`'s `/tmp` volume.
- **Push failed with `x509` on Harbor's `/service/token`**: `buildkitd.toml`'s CA covers the daemon's registry calls,
  but `buildctl` fetches the token itself. `SSL_CERT_DIR=/etc/ssl/certs:/etc/lab-ca` trusts the lab CA on top of
  the system roots. A hand-submitted build of `82b1c8a` then pushed `ci/smoke:82b1c8a…`.

## Secrets (seed → OpenBao → External Secrets)

`keycloak-argo-workflows-client-secret` → `secret/argo/sso` (Secret `argo/argo-server-sso`);
`harbor-ci-robot-secret` (Harbor's rules: 8–128 characters with upper, lower and a digit) → `secret/ci/harbor-robot`
(Secret `ci/harbor-push`, a Docker config). Namespaces `argo` and `ci` are on the ClusterSecretStore's allow-list.

## Layout

| Where | What |
|---|---|
| `k8s/platform/argo-workflows/` | chart values (SSO, `rootCA` kept by `scripts/pki-render.py`), `extras/`: the SSO ExternalSecret, `argo-admin` + its token Secret |
| `k8s/platform/argo-events/` | chart values: the controller, the pinned JetStream version |
| `k8s/platform/ci/` | namespace `ci` (PSA baseline), RBAC, the push login, BuildKit's config + the lab CA, EventBus, EventSource, Sensor, WorkflowTemplates `ci-poll` and `ci-build` |
| `ci/smoke/Dockerfile` | the milestone-2 build target |
| `terraform/identity/` | Keycloak client + group; Harbor project `ci` + robot |

Sync waves: Argo Workflows and Argo Events at 6 (after Keycloak 4 and Harbor 5), `ci` at 7. The workflow service
account and its Role are in `ci`, not the chart's, so nothing lands in `ci` before its namespace exists.

## Consequences

- Memory requests: about 0.5 GiB for the always-on parts (controller 128 MiB, server 64, Events controller 64, NATS
  96, EventSource + Sensor 64), plus 256 MiB per running build (2 GiB limit). [ADR 0002](0002-vm-sizing.md) log.
- A poll every 2 min is one small pod (`git ls-remote`); poll workflows are deleted after 10 min, builds after a
  day. Build logs stay in Loki.
- A new commit ships within about 2 minutes plus the build time. That's slower than a webhook, but needs no inbound path.
- Talos upgrades keep the patch (it's in the machine config); a newer moby profile is `scripts/seccomp-buildkit.py`
  with a new pin, then `scripts/tf.sh talos apply` (no reboot).
- Milestone 3 adds the real pipeline (sample-api: lint, test, Trivy, SBOM, cosign, tag bump) to `ci-build`.
